# Лабораторная работа №5. Агент на LangChain

## Что делает ассистент
Помощник первокурсника по учёбе и личному бюджету. Три инструмента:
- `save_note` — **пишет**: сохраняет заметку;
- `list_notes` — **читает**: возвращает сохранённые заметки;
- `calc_budget` — **считает**: остаток бюджета по четырём суммам (доход, жильё, еда, прочее).

## Как запустить
1. Рядом с ноутбуком создать файл `.env` с одной строкой: `LLM_API_KEY=<ваш ключ>`. Ноутбук читает его через `%dotenv`, поэтому ключ в коде не появляется.
2. Провайдер: Groq, эндпоинт `https://api.groq.com/openai/v1`, модель `openai/gpt-oss-120b`, `temperature=0`. Ключ берётся на console.groq.com/keys (бесплатный тариф, карта не нужна).
3. Runtime → Restart and run all.
4. Перед сдачей поиск по ноутбуку на `sk-`, `gsk_`, `api_key=`, `token`: ключа не должно быть ни в коде, ни в выводе.

## Структура ноутбука
0. Описание решения
1. Окружение: версии библиотек напечатаны (langchain 1.4.7, langgraph 1.2.18, langchain-openai 1.7.3)
2. Модель (`ChatOpenAI` с эндпоинтом Groq)
3. Инструменты и печать того, что видит модель (имя, описание, аргументы)
4. Агент `create_agent` с системным промптом и памятью `InMemorySaver`
5. Функция `show_calls` — лог вызовов инструментов
6. Четыре сценария и таблица результатов
7. Память живёт в `thread_id`
8. Эксперимент 1: описания инструментов ослаблены (выбор не сломался)
9. Эксперимент 2: нейтральные имена, одинаковая сигнатура, описания без подсказок (выбор сломался)
10. Эксперимент 3: те же инструменты и запросы, но с полными описаниями («Используй, когда…» / «Не используй…») (выбор восстановился)
11. Рефлексия

## Результаты
- Сценарии 1–4: общий вопрос — без вызовов; «запомни» — `save_note`; «что я просил записать» в новом потоке — `list_notes`, вернулась заметка; запрос без данных — агент запросил недостающие суммы и не выдумал их.
- Память: одинаковый вопрос в разных `thread_id` даёт разный результат.
- Эксперимент 1: при именах `save_…`/`list_…` и разных аргументах выбор не сломался.
- Эксперимент 2: при нейтральных именах, одинаковой сигнатуре и описаниях без подсказок инструмент не вызывался в двух из трёх запросов, которые его требовали. В одном случае агент написал «Запомню», не вызвав инструмент, — это разобрано в рефлексии.
- Эксперимент 3: те же имена, сигнатуры и запросы, но с полными описаниями. Оба запроса, требующих инструмента, вызвали нужный: "не дай забыть" — `tool_a`, "напомни" — `tool_b`. Контрольный запрос без инструментов не вызвал ничего. Вывод: в эксперименте 2 причиной сбоя были описания, а не модель и не системный промпт.

## Ограничения
- Заметки хранятся в памяти ноутбука (`NOTES`, `EXP_NOTES`): перезапуск ядра их очищает.
- `show_calls` печатает всю историю потока. Вызовы из предыдущих сценариев с тем же `thread_id` попадают в лог следующего (это видно в сценарии 4).
- Один прогон на запрос. `temperature=0` не гарантирует одинакового результата при повторном запуске.
- Бесплатный тариф Groq ограничен по числу запросов в минуту. При ошибке 429 подождать и повторить.
- Список моделей Groq меняется. Актуальный список: `GET https://api.groq.com/openai/v1/models`.
- Системный промпт соблюдается не всегда: в эксперименте 2 ответ был длиннее пяти предложений.

## Ключевые решения
- `parse_docstring=True` — без него блок `Args` не попадает в схему, которую видит модель. То есть, модель не "видит" телу функций, только его название, документация в виде `docstring` и аргументы. 
- `recursion_limit=15` — стоп-кран от зацикливания на вызовах инструментов.
- `thread_id` — где живёт память диалога; сам агент памяти не хранит.
